# 보안 검사와 제외 범위

검사일: 2026-11-14. 실제 비밀값은 문서·검사 출력에 기록하지 않았습니다.

## 수행 범위

- 원본의 소스·설정·스크립트·테스트·문서 등 텍스트 3,523개(약 60.4 MB)를 값 비노출 로컬 패턴 검사
- Gemini/OpenAI/GitHub 키 형식, 개인키, JWT, 세션 쿠키, 비밀번호·API 키 할당, 이메일 후보 확인
- 발견된 기존 저장소 1개의 Git 도달 가능한 전체 이력 검사: 전체 객체 220개, 텍스트 검사 대상 blob/commit 등 187개
- 공식 Gitleaks 8.30.1 배포물을 체크섬 확인 후 로컬 실행. 원본 `src`, 발견된 Git 이력, 최종 공개본을 추가 검사
- 공개본 전체 파일을 별도로 재검사. 계정·학습 데이터가 있는 원본 DB·덤프는 복사하지 않음

Gitleaks 도구 출처: [공식 v8.30.1 릴리스](https://github.com/gitleaks/gitleaks/releases/tag/v8.30.1). 검사는 로컬에서만 수행했습니다. 외부로 프로젝트 내용·설정·키를 보내지 않았습니다.

## 결과와 조치

| 대상 | 결과·조치 |
| --- | --- |
| 원본 DB 비밀번호 | 실제 값이 있는 설정을 확인. 설정 파일 전체를 공개본에서 제외하고 새 H2 설정 제공 |
| Gemini/OpenAI API 키 | 읽을 수 있었던 검사 범위에서 실제 키 형식 발견 0. 원본 설정은 환경변수 참조. 실제 환경변수 값은 열거·출력·복사하지 않음 |
| 기타 인증정보·쿠키·이메일 | 원본 패턴 검사 후보 220건. 백업·검증 로그·문서·가짜 fixture 등이 포함되며 모두 실제 비밀이라고 판단한 수치는 아님. 해당 원본 자료 일괄 제외 |
| Git 이력 | 자체 패턴 후보 13건, Gitleaks 후보 1건. Gitleaks 후보는 공개 CA 인증서 alias 검사 코드의 오탐으로 확인. 이전 이력은 결과와 관계없이 공개본에 복사하지 않음 |
| 최종 공개본 Gitleaks | 발견 0 |
| 최종 공개본 키·쿠키·개인키·JWT·리터럴 DB 설정 검사 | 발견 0 |
| 공개 계정·학습 기록 | 기존 데이터 미포함. 테스트 fixture·스크린샷은 합성 데이터. 실행 시 새 데모 소유자만 생성 |

원본에 대한 Gitleaks 후보 역시 같은 공개 인증서 alias 오탐이었습니다. 공개본에는 해당 줄에 사유를 적은 한 줄짜리 `gitleaks:allow`만 추가했으며, 광범위한 규칙 제외는 사용하지 않았습니다. 테스트의 `synthetic`·Mock 쿠키·example 이메일·비밀번호 편집기 변수 등은 실제 로그인 정보와 구분해 검토했습니다.

## 제외된 유형과 이유

| 제외 유형 | 이유 |
| --- | --- |
| 기존 `.git` | 민감정보 혼입과 불필요한 과거 이력 공개 방지. 저장소 초기화·commit도 수행하지 않음 |
| 실제 `application.properties`, 기존 시작 스크립트, 로컬 환경 설정 | 비밀번호·기기 경로·이전 실행 환경 의존 제거 |
| 기존 MySQL/H2 파일·덤프·계정 seed | 개인 계정과 학습 기록 보호, 원본 DB 보존 |
| 로그·세션·TLS/인증 자료·검토 승인 자료 | 쿠키·토큰·비밀·개인 데이터가 포함될 가능성 |
| `review-backups`, 단계별 `presentation-demo-*`, 포스터·과거 보고서 | 중복 소스·내부 작업 이력·검증 개인 자료 제외 |
| `.gradle`, `.dart_tool`, `build`, `node_modules`, IDE 설정 | 재생성 가능 캐시·기기 의존 파일 |
| APK/AAB/JAR 산출물·컴파일 JavaScript/WASM | 소스 배포와 빌드 절차로 재현. Gradle Wrapper JAR은 필수 빌드 도구로 예외 포함 |
| `.bak`, `.backup-*`, `.before-*`, 테스트 생성 보고서·스크린샷 | 이전 민감 설정·불필요한 산출물 제외. README용 합성 화면 3장만 선별 |

필요한 자동화 테스트·SQL fixture·Mock 데이터·PWA 폰트 라이선스는 유지했습니다. 테스트에서 생성한 계정 해시·H2·캐시·결과물은 최종 공개 폴더에서 제거하고 비공개 검증 자료 영역으로 옮겼습니다.

## 검사 한계와 향후 업로드 경계

원본의 보호된 검토/테스트 경로 49곳은 접근이 거부되어 내부 검사를 완료하지 못했습니다. 해당 경로는 공개본에 포함하지 않았고 우회하지 않았습니다. DB 바이너리·암호화 자료·압축 백업·의존성 바이너리의 내용은 텍스트 검사 범위에 포함하지 않았으며 배포 대상에서도 제외했습니다. 패턴 검사는 모든 형태의 비밀을 증명할 수 없으므로 새로운 파일을 추가하면 다시 검사해야 합니다.

공개 대상은 **이 폴더와 파일 목록에 있는 파일만**입니다. 상위 원본 프로젝트나 `_release-audit`를 업로드하지 마세요. 기존 Git 이력과 연결하지 않은 새 소스 이력으로 시작하는 것을 전제로 합니다. 사용자 승인 후에도 기존 원격 저장소 내용이 있다면 먼저 확인하고 덮어쓰기나 강제 push는 별도로 판단해야 합니다.

업로드 대상은 사용자가 제공한 비공개 저장소 `cafrijo-ux/ai-study-planner`입니다. 이 준비 단계에서는 원격 저장소 쓰기·commit·push·공개 전환을 하지 않았습니다.

## 재검사

```powershell
node tools/scan-public.cjs
gitleaks dir . --redact=100 --no-banner
# Git 이력을 만든 후 별도 검사
gitleaks git . --redact=100 --no-banner
```

자체 검사기는 비밀값을 출력하지 않고 파일·규칙·줄 번호만 출력합니다. Gitleaks 검사도 redaction 옵션을 유지하세요. 실제 키·비밀번호·세션 값은 보고서·이슈·스크린샷·대화에 붙여 넣지 않습니다.
